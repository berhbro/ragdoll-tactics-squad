# 《布娃娃战术小队》展示视频分镜与拍摄规划

> 目标时长：4 分 30 秒以内，绝不超过 5:00。下面的时间是剪辑目标，不是必须的实际时长。
>
> 重要标记：`HUMAN PLAY` 是真人操作；`WATCH DEMO` 是游戏内自动 Demo。两段必须分开录制和标注。

## 1. 目标观众与核心信息

- **目标观众**：15–25 岁、喜欢短流程战术游戏和物理喜剧、希望用几分钟完成一局的 PC 浏览器玩家。
- **核心卖点**：玩家不是直接控制一个角色，而是指挥三人小队排雷、交火、救援，并观察布娃娃物理带来的意外结果。
- **一句话介绍**：指挥工兵、步枪手和机枪手穿过雷区，消灭电台守军并完成占领。
- **观众看完应理解**：游戏怎么操作、胜利目标是什么、布娃娃和排雷如何影响决策，以及团队如何依据真实试玩改进游戏。

## 2. 拍摄前检查清单

### 游戏检查

- [ ] 从提交目录启动游戏，不依赖远程服务或开发工具。
- [ ] 能正常进入开始菜单和正常游戏。
- [ ] “观看演示 / Watch Demo”按钮可见。
- [ ] 点击 Demo 后不需要继续操作，脚本能自动推进。
- [ ] Demo 使用真实游戏对象、移动、交互、音效和占领系统，而不是预录视频。
- [ ] Demo 结束后能返回菜单，或能退出并重新开始正常游戏。
- [ ] 音效可听见，静音/音量控制可展示。
- [ ] 录制浏览器窗口时隐藏开发者工具、账号信息和私人通知。

### 资料检查

- [ ] 确认所有出镜成员同意录制；手部画面即可，不要求露脸。
- [ ] 外部试玩记录使用匿名标签，不录入姓名、学号或联系方式。
- [ ] 试玩者原话和团队观察必须来自真实记录，不使用 AI 编造或润色。
- [ ] 确认外部音效、模型和音乐的来源及授权，并写入小组报告。
- [ ] 每次改动后重新运行游戏再录制。

## 3. 分镜表

### 0:00–0:15 — 开场钩子

- **画面**：快速剪辑爆炸、敌人倒地、队员救援、电台读条和胜利画面。
- **字幕**：`布娃娃战术小队 / Ragdoll Tactics Squad`。
- **旁白建议**：
  > 三名队员，一片雷区，一个必须夺下的电台。每一次移动都可能让小队被炸飞。
- **目的**：先展示玩家体验，不要先讲技术栈。

### 0:15–0:35 — 团队与任务

- **画面**：成员姓名/角色卡，配合游戏画面小窗。
- **内容**：
  - A：工程、输入、相机和核心系统
  - B：地图、小队移动和战斗
  - C：角色资源、地雷、物理和救援
  - D：Demo、视频和展示
  - E：UI 和音效
- **字幕**：`One short level · Browser 3D game · Three.js + Rapier3D`。
- **注意**：必须根据最终真实分工修改姓名和职责。

### 0:35–1:35 — HUMAN PLAY：真人游玩

- **画面**：屏幕录制加键盘鼠标/手部画面；明确显示 `HUMAN PLAY / 真人游玩`。
- **操作镜头**：
  1. 点击开始游戏。
  2. 左键选择工兵，右键移动。
  3. 探雷器发出提示，工兵排雷。
  4. 选择步枪手和机枪手，向敌人推进并交火。
  5. 展示一次倒地、救援或爆炸物理（如果当前版本稳定）。
  6. 进入电台范围，展示占领进度和胜利结果。
- **旁白建议**：
  > 我用右键下达移动命令，工兵负责处理地雷；遭遇敌人后，小队会寻找掩体并开火。玩家需要在推进速度和队员安全之间做选择。
- **录制要求**：保留真实鼠标点击和键盘操作，不要把 Demo 录像冒充真人游玩。

### 1:35–2:35 — WATCH DEMO：游戏内自动演示

- **画面**：回到开始菜单，点击 `观看演示 / Watch Demo`；显示 `WATCH DEMO / 自动演示`。
- **脚本流程**：
  1. 自动选择工兵。
  2. 移动到主路雷区。
  3. 对 `mine_1` 发起排雷交互。
  4. 自动选择三名队员并推进。
  5. 对 `E06` 发起攻击交互。
  6. 追加移动到电台区域。
  7. 对 `E08` 发起攻击交互。
  8. 开始占领并显示读条。
  9. 自动结束并展示胜利。
- **旁白建议**：
  > 这是游戏内的自动 Demo，不是预录视频。它调用和真人相同的移动、交互与占领流程，让观众在没有操作的情况下看到一局的核心节奏。
- **注意**：如果某项功能在最终版本不稳定，应删掉对应动作并重新录制，不要在视频中声称不存在的功能已经完成。

### 2:35–3:05 — 核心体验特写

- **画面**：分屏或连续特写。
- **依次展示**：
  - 动态俯角相机和缩放
  - 探雷器视觉/声音反馈
  - 红、黄、绿悬停指示器
  - 爆炸后的布娃娃效果
  - 救援读条
  - 电台占领进度
  - 静音/音量按钮
- **字幕原则**：用玩家收益描述功能，例如：
  - `更近看细节，拉远看全局`
  - `声音越急，地雷越近`
  - `倒地不是立即失败：队友可以救援`

### 3:05–3:40 — 外部试玩反馈

- **画面**：真实试玩片段或匿名反馈卡片；标记 `EXTERNAL PLAYTEST`。
- **必须填入真实内容**：
  - 匿名试玩者标签
  - 大致年龄范围、角色/情境、游戏频率
  - 试玩者尝试了什么
  - 团队直接观察到什么
  - 试玩者原话或忠实记录
- **旁白模板**：
  > 我们让组外试玩者在没有讲解的情况下尝试游戏。我们观察到【真实观察】，试玩者说：“【真实原话】”。
- **禁止**：不要使用 AI 生成、翻译、润色试玩反馈或观察。

### 3:40–4:10 — 两次迭代

- **画面**：修改前/修改后对比，或 commit/截图/录屏对比。
- **第一次迭代**：必须由外部试玩问题触发。
- **第二次迭代**：展示团队测试发现的另一个问题。
- **每次必须说明**：
  1. 我们亲自观察到的问题
  2. 做了什么修改
  3. 谁实现或检查
  4. 重新测试的结果
- **注意**：该部分属于课程 NO AI 记录，视频可以帮助展示，但事实必须来自团队自己的记录。

### 4:10–4:30 — 结尾与行动号召

- **画面**：小队站在电台、胜利面板或最有趣的布娃娃镜头。
- **字幕**：
  - `Plan the route. Clear the mines. Take the radio.`
  - `布娃娃战术小队`
  - `Thank you for watching`
- **旁白建议**：
  > 《布娃娃战术小队》用一个短小的关卡，把战术决策和物理喜剧放在同一局游戏里。谢谢观看。

## 5. D 的交付物

- `src/demo/DemoPlayer.ts`：数据驱动 Demo 播放器框架
- `public/data/demoPath01.json`：可重复的 Demo 动作脚本
- `docs/video/storyboard.md`：分镜和拍摄规划
- `W05_GroupID_Game_Demo.mp4`：最终视频（由团队在游戏可玩后录制和剪辑）
- `docs/ai-interactions/` 中的真实 AI 使用记录（如 Demo 开发使用了 AI）

## 6. 当前限制与联调依赖

主项目目前仍有部分模块处于骨架阶段。Demo 脚本中的单位 ID、敌人 ID、地雷 ID 和坐标必须在 A/B/C 完成实体生成后联调确认。当前脚本使用：

- 队员：`engineer`、`rifleman`、`machinegunner`
- 地雷：`mine_1`
- 敌人：`E06`、`E08`
- 电台：地图数据中的 `{ x: 15, y: 0, z: 15 }`

如果实际实现采用不同 ID，应同步修改 `demoPath01.json`，并重新测试完整 Demo。
